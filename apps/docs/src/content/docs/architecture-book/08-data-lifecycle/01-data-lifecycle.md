# Жизненный цикл данных

## Статус

Accepted

---

## Введение

Цифровой мир существует во времени.

Автомобили меняют состояние.

Камеры появляются и выводятся из эксплуатации.

Отношения создаются и прекращаются.

События накапливаются.

Файлы загружаются.

Проекции пересчитываются.

Если платформа хранит всё одинаково и бесконечно, со временем стоимость хранения и обработки начинает расти независимо от реальной ценности информации.

Поэтому данные должны иметь определённый жизненный цикл.

---

## Основной принцип

Данные существуют столько и в той форме, сколько требует их смысл.

```text
Created
   │
   ▼
Active
   │
   ▼
Historical
   │
   ▼
Archived
   │
   ▼
Deleted
```

Не каждый тип данных обязан пройти все этапы.

---

## Данные имеют различную природу

В «Призме» могут существовать:

- текущее авторитетное состояние;
- история изменений;
- события;
- проекции;
- телеметрия;
- файлы и вложения;
- медиаданные;
- кэш;
- технические логи.

Для каждого класса действуют разные правила хранения.

---

## Пример

Автомобиль существует в цифровом мире пять лет.

За это время могут накопиться миллионы координат.

```text
Vehicle
  │
  ├── Current state
  ├── Recent telemetry
  ├── Historical telemetry
  └── Archived telemetry
```

Текущее состояние должно быть доступно быстро.

Координаты за вчера могут использоваться часто.

Данные трёхлетней давности могут понадобиться только для расследования или отчёта.

Одинаковая storage policy для всех этих данных не требуется.

---

## Lifecycle является частью архитектуры

Нельзя откладывать вопрос хранения до момента, когда база станет слишком большой.

Для каждого значимого типа данных заранее определяются:

```text
Data type
   │
   ├── owner
   ├── source of truth
   ├── retention
   ├── storage tier
   ├── archival
   └── deletion policy
```

---

## Lifecycle и цифровой мир

Удаление технических данных не должно случайно разрушать смысл цифрового мира.

Если объект удалён из активного использования, это не обязательно означает физическое уничтожение всей его истории.

```text
Vehicle retired
      │
      ├── active projection removed
      └── historical record retained
```

Решение определяется предметной моделью.

---

## Lifecycle и производные данные

Проекция и cache имеют другой жизненный цикл, чем авторитетное состояние.

```text
Authoritative State
       │
       ├── protected
       │
       ▼
Projection
       │
       └── rebuildable
```

Если производные данные можно пересоздать, их потеря не должна считаться потерей цифрового мира.

---

## Практическое значение

Lifecycle позволяет управлять:

- объёмом хранилища;
- стоимостью;
- скоростью запросов;
- требованиями к backup;
- сроками хранения;
- удалением;
- восстановлением;
- историческими исследованиями.

---

## Инварианты

- Каждый значимый класс данных имеет определённого владельца.
- Авторитетное и производное состояние различаются.
- Retention определяется смыслом данных, а не одной глобальной политикой.
- Архивирование не должно незаметно менять предметную семантику.
- Удаление выполняется контролируемо.
- Производные данные по возможности остаются пересоздаваемыми.
- Lifecycle учитывается до достижения предельного объёма хранения.

---
