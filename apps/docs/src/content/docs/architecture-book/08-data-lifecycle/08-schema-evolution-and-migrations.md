# Эволюция схемы и миграции данных

## Статус

Accepted

---

## Введение

Через несколько лет структура объектов «Призмы» неизбежно изменится.

Добавятся свойства.

Изменятся отношения.

Появятся новые типы данных.

Но существующая история не должна становиться нечитаемой.

---

## Schema evolution

```text
Schema v1
   │
   ▼
Schema v2
   │
   ▼
Schema v3
```

Изменение схемы является управляемым архитектурным процессом.

---

## Backward compatibility

Во время rolling deployment старая и новая версии приложения могут работать одновременно.

```text
Service v1
Service v2
    │
    ▼
Same storage
```

Миграция не должна мгновенно требовать единственной версии runtime, если deployment model допускает coexistence.

---

## Expand and contract

Безопасная модель изменения:

```text
Expand
  │
Both formats supported
  │
Migrate
  │
Contract
```

Сначала добавляется новая структура без разрушения старой.

Затем данные мигрируются.

После завершения поддержки старая структура удаляется.

---

## Historical formats

Архивные данные могут храниться в старом формате.

Необходимо либо:

- сохранять reader старой версии;
- мигрировать архив;
- использовать versioned serialization.

---

## Data migration

Большая миграция не должна обязательно выполняться одной блокирующей транзакцией.

```text
Millions of records
       │
       ▼
Batch migration
       │
       ▼
Progress / checkpoint
```

Процесс должен быть restartable и наблюдаемым.

---

## Validation

После миграции проверяется не только количество строк, но и сохранение предметного смысла.

```text
Before
  │
Migration
  │
After
  │
Invariant validation
```

---

## Инварианты

- Schema changes versioned и контролируемы.
- Rolling deployment учитывает coexistence версий.
- Разрушающие изменения выполняются через безопасную migration strategy.
- Большие миграции restartable.
- Migration progress наблюдаем.
- Исторические форматы остаются читаемыми.
- После миграции проверяются Domain Invariants.

---

## Заключение

Lifecycle-процессы должны работать не только в штатном режиме, но и при ошибках. Следующая страница определяет их наблюдаемость и восстановление.
