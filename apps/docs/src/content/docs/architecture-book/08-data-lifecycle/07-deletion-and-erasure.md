# Удаление данных

## Статус

Accepted

---

## Введение

Удаление является изменением состояния, а не простой SQL-командой.

Необходимо понимать:

- что именно удаляется;
- кто имеет право удалить;
- какие зависимости существуют;
- должна ли сохраниться история;
- когда допустимо физическое уничтожение.

---

## Logical deletion

Объект может перестать быть активным, сохраняя историческую identity.

```text
Vehicle
  │
Active
  │
Retired
```

Такой объект может исчезнуть из обычной рабочей проекции, но оставаться в истории.

---

## Physical deletion

Физическое удаление означает уничтожение данных из хранилища.

```text
Data
 │
 ▼
Erase
 │
 X
No longer recoverable
```

Это значительно более сильная операция.

---

## Tombstone

В распределённых процессах иногда требуется сохранить факт удаления.

```text
Object 42 deleted
       │
       ▼
Tombstone
```

Иначе отставшая система может повторно создать устаревшее представление объекта.

---

## Referential integrity

Перед удалением необходимо учитывать связи.

```text
Vehicle 42
 ├── history
 ├── attachments
 ├── relations
 └── projections
```

Удаление не должно оставлять невалидные ссылки.

---

## Erasure workflow

Для сложного удаления полезен явный процесс:

```text
Deletion requested
      │
Authorization
      │
Dependency check
      │
Mark deleted
      │
Cleanup projections/files
      │
Physical erasure when allowed
```

---

## Backup problem

Физическое удаление из active storage не означает мгновенное исчезновение из backup.

Политика должна определять, как erasure сочетается с backup retention и restore.

---

## Инварианты

- Logical и physical deletion различаются.
- Удаление проходит authorization и предметные проверки.
- Историческая identity не уничтожается автоматически.
- Referential integrity сохраняется.
- Распределённые consumers получают способ узнать об удалении.
- Erasure учитывает backup lifecycle.
- Удаление является наблюдаемым и аудируемым процессом там, где это требуется.

---

## Заключение

Данные живут дольше отдельных версий программного обеспечения. Поэтому их формат должен эволюционировать без потери смысла.
