# Текущее и историческое состояние

## Статус

Accepted

---

## Введение

Платформа должна быстро отвечать на два разных вопроса:

> Что происходит сейчас?

и:

> Что происходило раньше?

Эти запросы используют один цифровой мир, но имеют разные access patterns.

---

## Current State

Текущее состояние представляет последнюю согласованную версию объекта.

```text
Vehicle 42
   │
   ├── status
   ├── position
   ├── assigned route
   └── current relations
```

Оно оптимизировано под актуальные операции.

---

## Historical State

История описывает развитие объекта во времени.

```text
v101 → v102 → v103 → v104
                     │
                     ▼
                  current
```

История может включать:

- версии;
- события;
- интервалы состояний;
- телеметрию;
- аудит изменений.

---

## Пример

Сейчас автомобиль находится на парковке.

Но пользователь хочет узнать его маршрут вчера.

```text
Current State
Vehicle → Parking

Historical Query
Yesterday 08:00 ───────── 18:00
       route positions
```

Current State не обязан содержать все вчерашние координаты.

---

## История не должна замедлять текущие операции

Если таблица текущих объектов вынуждена постоянно сканировать миллиарды исторических записей, storage model плохо соответствует workload.

```text
Current query
     │
     X
Huge history scan
```

Исторические и текущие access patterns могут иметь разные физические представления.

---

## Восстановление состояния на момент времени

Если архитектура поддерживает historical reconstruction:

```text
Time T
  │
  ▼
Version / events
  │
  ▼
State at T
```

необходимо определить точность и стоимость такого восстановления.

Не вся телеметрия обязана становиться Domain Version.

---

## История и версии

Версия фиксирует предметное изменение состояния.

Телеметрическая точка может быть просто наблюдением.

```text
Domain Version
      ≠
Every telemetry sample
```

Иначе высокочастотные источники способны искусственно раздуть предметную историю.

---

## Инварианты

- Current State и Historical State имеют разные access patterns.
- Текущие операции не зависят от полного сканирования истории.
- Не каждая телеметрическая точка является Domain Version.
- Историческая реконструкция имеет определённую семантику.
- История не заменяет текущее авторитетное состояние без явного архитектурного решения.

---

## Заключение

История со временем растёт. Следующий вопрос — сколько времени разные данные должны оставаться доступными.

Это определяет **retention policy**.
