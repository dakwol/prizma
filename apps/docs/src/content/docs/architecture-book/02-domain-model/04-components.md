# Компоненты

## Статус

Accepted

---

## Введение

Объект определяет существование сущности.

Компоненты определяют её содержание.

Архитектура платформы исходит из принципа, что объект не должен содержать знания о предметной области.

Все особенности объекта выражаются через компоненты.

---

## Почему компоненты

Со временем любая информационная система начинает расширяться.

Появляются новые свойства.

Новые возможности.

Новые интеграции.

Если все изменения вносятся непосредственно в объект, он постепенно становится центром всей системы.

Это приводит к высокой связанности, сложному сопровождению и невозможности повторного использования архитектурных решений.

Использование компонентов позволяет избежать этой проблемы.

---

## Один компонент — одна ответственность

Каждый компонент отвечает только за одну область знаний.

Компонент не должен описывать несколько независимых аспектов объекта одновременно.

Например:

Недопустимо создавать компонент, который одновременно хранит пространственное положение объекта, права доступа и настройки отображения.

Вместо этого каждая область ответственности должна быть выделена в самостоятельный компонент.

---

## Независимость компонентов

Компоненты должны быть максимально независимыми друг от друга.

Добавление нового компонента не должно требовать изменения существующих.

Удаление компонента не должно нарушать работу остальных.

Компоненты взаимодействуют через объект, а не напрямую между собой.

---

## Компоненты определяют возможности объекта

Архитектура платформы не содержит фиксированных типов объектов.

Два объекта могут обладать различными возможностями исключительно благодаря различному набору компонентов.

Таким образом объект остаётся универсальной архитектурной конструкцией независимо от предметной области.

---

## Компоненты могут появляться и исчезать

Наличие компонента не является постоянным.

Во время жизненного цикла объекта состав компонентов может изменяться.

Добавление компонента расширяет возможности объекта.

Удаление компонента ограничивает их.

При этом идентичность объекта остаётся неизменной.

---

## Компонент не является объектом

Компонент не обладает собственной идентичностью.

Он существует только как часть объекта.

Удаление объекта автоматически завершает существование всех принадлежащих ему компонентов.

---

## Наследование не используется

Компоненты являются механизмом расширения модели.

Архитектура платформы не использует наследование предметных сущностей как основной способ моделирования.

Новые возможности достигаются добавлением новых компонентов, а не созданием новых иерархий классов.

---

## Эволюция платформы

Большинство изменений в платформе должны происходить путём создания новых компонентов.

Расширение ядра рассматривается как исключительная ситуация.

Это позволяет платформе развиваться без изменения фундаментальной архитектуры.

---

## Заключение

Компоненты являются основным механизмом развития платформы.

Ядро остаётся небольшим и неизменным.

Предметная область развивается за счёт появления новых компонентов, а не усложнения базовой модели объектов.
