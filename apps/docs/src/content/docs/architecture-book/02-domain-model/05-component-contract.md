# Контракт компонента

## Статус

Accepted

---

## Введение

Компоненты являются основным механизмом расширения модели мира.

Чтобы любой компонент мог существовать в системе независимо от предметной области, все компоненты обязаны соответствовать единому контракту.

Контракт определяет не программный интерфейс, а архитектурные обязательства компонента.

Любая реализация компонента должна соблюдать данные правила.

---

## Назначение

Компонент описывает один аспект объекта.

Он не определяет существование объекта.

Он определяет только одну область знаний о нём.

Компонент не должен выходить за пределы собственной ответственности.

---

## Принадлежность

Каждый компонент принадлежит ровно одному объекту.

Компонент не может существовать самостоятельно.

Перенос компонента между объектами рассматривается как удаление компонента у одного объекта и создание нового у другого.

---

## Ответственность

Каждый компонент отвечает только за собственное состояние.

Компонент не должен хранить данные, относящиеся к ответственности другого компонента.

Если для описания поведения требуется несколько независимых областей знаний, они должны быть представлены отдельными компонентами.

---

## Независимость

Компоненты должны быть максимально независимыми.

Изменение внутренней реализации одного компонента не должно требовать изменения остальных компонентов объекта.

Компоненты взаимодействуют через объект и публичные контракты платформы.

Прямые зависимости между компонентами должны быть сведены к минимуму.

---

## Состояние

Компонент обладает собственным состоянием.

Это состояние принадлежит только данному компоненту.

Никакой другой компонент не должен изменять его напрямую.

Все изменения выполняются через механизмы платформы.

---

## Уникальность

Для каждого типа компонента внутри одного объекта может существовать не более одного экземпляра.

Если объект уже содержит компонент определённого типа, повторное добавление такого же компонента запрещается.

Это правило обеспечивает однозначность модели.

---

## Жизненный цикл

Жизненный цикл компонента полностью определяется жизненным циклом объекта.

Компонент может:

- быть создан;
- изменяться;
- быть удалён.

Удаление объекта завершает жизненный цикл всех принадлежащих ему компонентов.

---

## Инварианты

Каждый компонент обязан самостоятельно обеспечивать корректность собственного состояния.

Компонент не должен существовать в некорректном состоянии.

Если необходимые условия нарушены, изменение должно быть отклонено.

---

## Побочные эффекты

Компонент не должен самостоятельно изменять состояние других компонентов.

Если изменение одного компонента требует реакции системы, такая реакция должна быть выражена через события, сценарии или другие механизмы платформы.

Компоненты не должны содержать скрытых зависимостей друг от друга.

---

## Расширяемость

Добавление нового типа компонента не должно требовать изменения существующих компонентов.

Если появление нового компонента приводит к необходимости изменить множество уже существующих компонентов, архитектурное решение считается неверным.

Платформа должна расширяться путём добавления нового, а не изменения существующего.

---

## Версионирование

Изменение структуры компонента не должно нарушать совместимость модели мира.

Если изменение несовместимо с предыдущей версией контракта, должна быть определена стратегия миграции.

Контракт компонента рассматривается как публичная часть архитектуры платформы.

---

## Заключение

Контракт компонента обеспечивает единообразие всей платформы.

Независимо от предметной области, технологии реализации или состава команды каждый новый компонент обязан соответствовать единым архитектурным правилам.

Именно это позволяет платформе масштабироваться без усложнения её фундаментальной модели.
