# Развёртывание и эксплуатация

## Статус

Accepted

---

## Введение

Архитектура существует не только в исходном коде.

Чтобы цифровой мир работал, программное обеспечение необходимо:

- собрать;
- настроить;
- развернуть;
- обновить;
- наблюдать;
- восстановить после неудачного изменения.

Deployment & Operations связывает архитектуру приложения с реальной инфраструктурой.

---

## Основной принцип

Развёртывание является частью жизненного цикла системы.

```text
Source
  │
  ▼
Build
  │
  ▼
Artifact
  │
  ▼
Deploy
  │
  ▼
Verify
  │
  ▼
Operate
```

Поставка не заканчивается успешным запуском процесса.

Необходимо доказать, что новая версия действительно способна обслуживать требуемый workload.

---

## Deployment Unit

Deployment Unit — часть системы, которая может поставляться и запускаться независимо.

```text
Platform
  │
  ├── API
  ├── Worker
  ├── Realtime
  ├── Media
  └── Edge components
```

Логический модуль не обязан быть отдельным deployment unit.

И наоборот, один deployment unit может содержать несколько логических модулей.

---

## Пример

Transport и Camera могут быть отдельными Domain Modules, но на раннем этапе работать внутри одного backend process.

```text
Backend
 ├── Transport Module
 ├── Camera Module
 └── World Module
```

Это не нарушает модульную архитектуру.

Физическое разделение появляется только при эксплуатационной необходимости.

---

## Immutable artifact

Предпочтительная модель:

```text
Build once
   │
   ▼
Artifact
   │
   ├── Dev
   ├── Test
   └── Production
```

Между окружениями меняется конфигурация, а не собранный код.

---

## Deployment и состояние

Stateless runtime проще заменять и масштабировать.

Критическое состояние хранится в предназначенных для этого устойчивых системах.

```text
Process X
   │
restart
   │
Process ✔
   │
State restored from durable sources
```

---

## Operations

Эксплуатация включает:

- health;
- observability;
- scaling;
- backup;
- recovery;
- configuration;
- incident response;
- lifecycle jobs;
- deployment control.

Это не отдельная деятельность после архитектуры.

Она является её продолжением.

---

## Инварианты

- Deployment topology не определяет Domain boundaries.
- Build artifact не изменяется между окружениями без необходимости.
- Критическое состояние не хранится только в памяти runtime process.
- Deployment завершается проверкой работоспособности.
- Независимый deployment используется там, где даёт эксплуатационную ценность.
- Operations учитывается при проектировании компонента.

---

## Заключение

Следующая страница определяет модель environments платформы.
