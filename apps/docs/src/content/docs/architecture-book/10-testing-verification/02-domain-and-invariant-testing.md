# Проверка Domain Invariants

## Статус

Accepted

---

## Введение

Domain Invariant определяет состояние, в котором цифровой мир имеет смысл.

Если инвариант нарушен, технически успешная запись в базу всё равно является архитектурной ошибкой.

---

## Проверка переходов

Тестируется не только итоговое значение, но и допустимость перехода.

```text
State A
  │
Command
  │
  ▼
State B
```

Необходимо проверить:

- допустимый переход;
- запрещённый переход;
- пограничные значения;
- сохранение остальных инвариантов.

---

## Пример

Пусть камера может быть привязана только к существующему объекту площадки.

```text
Attach Camera
     │
     ▼
Target exists?
  ┌──┴──┐
 yes    no
  │      │
 ✔       X
```

Тест должен доказать оба сценария.

---

## Не тестировать реализацию вместо правила

Плохо:

> был ли вызван внутренний private method `validateTarget`.

Полезнее:

> невозможно ли получить состояние с невалидной привязкой.

Внутренняя реализация может измениться, а инвариант остаётся.

---

## Property-based testing

Для математических и комбинаторных правил полезна генерация множества входных данных.

```text
Generated states
      │
      ▼
Domain operation
      │
      ▼
Invariant always holds?
```

Это особенно полезно для:

- диапазонов;
- геометрии;
- преобразований;
- последовательностей переходов.

---

## Sequence testing

Некоторые ошибки возникают только после цепочки операций.

```text
Create
  │
Assign
  │
Move
  │
Detach
  │
Archive
```

Тестируется не только отдельная команда, но и допустимые последовательности жизненного цикла.

---

## Инварианты

- Каждый критический Domain Invariant имеет проверяемое выражение.
- Тесты ориентированы на публичное предметное поведение.
- Запрещённые состояния проверяются так же, как допустимые.
- Последовательности операций тестируются там, где состояние зависит от истории.
- Property-based подход используется там, где пространство входов слишком велико для нескольких примеров.
- Domain tests не требуют реальной инфраструктуры, если правило от неё не зависит.

---

## Заключение

Domain Model не существует изолированно. Она сохраняется в storage и взаимодействует с инфраструктурой.
