# Тестовые данные и окружения

## Статус

Accepted

---

## Введение

Тест может быть корректным только при известном исходном состоянии.

Общий стенд, который вручную меняют десятки разработчиков, плохо подходит для доказательства воспроизводимости.

---

## Deterministic data

```text
Known input world
       │
       ▼
Operation
       │
       ▼
Known expected world
```

Тестовые данные создаются программно или из versioned fixtures.

---

## Representative data

Слишком маленькие искусственные datasets могут скрывать проблемы.

Например:

```text
10 objects  → works
100000      → different behavior
```

Для performance и migration testing нужны объёмы, близкие к реальным характеристикам.

---

## Production data

Реальные production datasets могут содержать чувствительную информацию.

Их нельзя автоматически копировать в development environment.

Если реальные структуры нужны для диагностики, используется контролируемая anonymization/sanitization strategy.

---

## Time

Времязависимая логика должна позволять контролировать clock.

```text
System clock abstraction
        │
        ▼
Known test time
```

Иначе проверки retention, expiration и historical queries становятся нестабильными.

---

## External dependencies

Тестовое окружение должно явно показывать, какие зависимости:

- реальные;
- локальные;
- simulated;
- unavailable.

Это влияет на силу доказательства теста.

---

## Инварианты

- Test setup воспроизводим.
- Tests не зависят от случайного состояния общего стенда без необходимости.
- Большие workload tests используют representative datasets.
- Production data не копируется бесконтрольно.
- Time-dependent logic тестируется с контролируемым временем.
- Уровень реалистичности внешних dependencies известен.
- Test data cleanup не должен влиять на параллельные тесты.
