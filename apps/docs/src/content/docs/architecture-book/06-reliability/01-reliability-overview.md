# Надёжность

## Статус

Accepted

## Введение

Отказ является нормальным состоянием распределённой системы. Сеть, внешний API, отдельный процесс, проекция, камера или edge-узел могут временно быть недоступны.

Надёжность означает способность «Призмы» сохранять корректность, доступность независимых функций и возможность восстановления при отказе отдельных частей.

## Основной принцип

```text
Partial failure ≠ Platform failure
```

```text
Dependency X
    │
    ▼
Affected capability
    │
    ├── degraded
    └── isolated

Digital World continues
```

## Пример

GPS-провайдер перестал передавать координаты автомобилей.

Это означает, что новые координаты не поступают и последнее известное положение постепенно становится устаревшим.

Это не означает, что автомобиль исчез, история потеряна или вся карта должна перестать работать.

```text
GPS Provider X
      │
      ▼
Position updates stopped
      │
      ├── Last known position remains
      ├── Freshness becomes stale
      └── Other capabilities continue
```

## Failure Domain

Failure Domain — область, отказ которой способен происходить независимо: процесс, сервис, БД, брокер, интеграция, edge-узел или площадка.

Архитектура должна ограничивать распространение отказа этой областью настолько, насколько позволяет предметная модель.

## Надёжность и согласованность

Доступность не достигается ценой нарушения инвариантов.

Если операцию нельзя выполнить корректно, она должна быть отклонена или отложена.

```text
Can execute safely?
      │
   ┌──┴──┐
  yes    no
   │      │
execute  reject/defer
```

## Практическое значение

Для каждой зависимости необходимо определить:

```text
Can it fail?
    │
What stops working?
    │
Can failure be isolated?
    │
What degraded mode exists?
    │
How does recovery work?
```

## Инварианты

- Частичный отказ не считается автоматически отказом всей платформы.
- Отказы имеют ограниченную область распространения.
- Деградация не нарушает Domain Invariants.
- Потеря актуальности данных отображается явно.
- Отказы наблюдаемы.
- Восстанавливаемые процессы имеют определённый recovery path.

## Заключение

Для правильной реакции сначала необходимо понимать природу отказа. Следующая страница определяет модель отказов платформы.
