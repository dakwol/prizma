# Режим деградации

## Статус

Accepted

## Введение

Система не обязана находиться только в состояниях «работает» и «сломана». Контролируемая деградация сохраняет независимые безопасные функции и явно показывает ограничения.

## Основной принцип

```text
Capability unavailable
        │
        ▼
Explicit degradation
 ├── preserve safe functions
 ├── expose stale state
 └── disable unsafe actions
```

## GPS

При недоступности GPS:

```text
Vehicle identity       ✔
Last known position    ✔
History                ✔
Fresh telemetry        X
Freshness              stale
```

Объект остаётся на карте, но UI явно показывает устаревание координаты.

## Камеры

При падении Media Service метаданные камеры и история могут оставаться доступными, хотя live stream и PTZ временно недоступны.

## Stale, unknown и unavailable

Эти состояния не взаимозаменяемы.

`stale` — значение известно, но устарело.

`unknown` — текущее значение неизвестно.

`unavailable` — источник или возможность сейчас недоступны.

## Fail closed

Если security-sensitive проверку невозможно выполнить, безопасным поведением по умолчанию является запрет.

```text
Authorization unavailable
          │
          ▼
         deny
```

## Edge autonomy

Edge может продолжать заранее разрешённые локальные операции при потере центра только при явно определённых границах владения и последующей синхронизации.

## Инварианты

- Деградация отображается явно.
- Stale, unknown и unavailable различаются.
- Последнее известное значение не выдаётся за актуальное.
- Независимые безопасные функции продолжают работу.
- Небезопасные действия отключаются и отклоняются backend.
- Security-critical проверки fail closed.
- Автономность edge определяется заранее.

## Заключение

После возвращения зависимости требуется не только включить трафик, но и восстановить согласованность. Это задача recovery и reconciliation.
