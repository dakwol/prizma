# Цифровой мир как центр архитектуры

## Статус

Accepted

---

## Основной принцип

В центре «Призмы» находится не карта.

Не таблица.

Не камера.

Не API.

В центре находится цифровой мир.

```text
              Interfaces
                  │
                  ▼
Analytics ──► Digital World ◄── Integrations
                  ▲
                  │
              Automation
```

Все остальные механизмы либо изменяют его, либо представляют, либо наблюдают.

---

## Что содержит цифровой мир

В общем виде:

```text
Digital World
   │
   ├── Objects
   │     └── Components
   │
   ├── Relations
   │
   ├── States
   │
   ├── Events
   │
   ├── Versions
   │
   └── History
```

Это не обязательно одна физическая структура хранения.

Это единая предметная модель.

---

## Объект

Object даёт сущности устойчивую Identity.

Например:

```text
Vehicle #42
```

Один и тот же автомобиль может менять:

- координату;
- состояние;
- назначение;
- характеристики;
- отношения.

Но его Identity сохраняется.

---

## Component

Component описывает отдельную способность или аспект объекта.

```text
Vehicle #42
   │
   ├── Position
   ├── Movement
   ├── Status
   └── Ownership
```

Так модель развивается композиционно, а не через бесконечные универсальные типы объектов.

---

## Relation

Relation делает связи частью цифрового мира.

```text
Camera ── installed_on ──► Building
Vehicle ── assigned_to ──► Route
```

Связь имеет собственный смысл и lifecycle.

---

## State и History

Мир существует одновременно как:

```text
Current State
     +
Historical Development
```

Текущее состояние отвечает на вопрос «что сейчас».

История отвечает «как мы сюда пришли».

---

## Мир не равен проекции

```text
Digital World
     │
     ├── Map
     ├── Table
     ├── Report
     └── API View
```

Карта является только одним представлением.

Если карта перестала существовать, цифровой мир не должен потеряться.

---

## Инварианты

- Digital World является центром предметной архитектуры.
- UI не является источником истины.
- Object Identity сохраняется через изменения состояния.
- Components описывают аспекты объектов.
- Relations являются частью модели.
- Current State и History различаются.
- Projection не становится владельцем Domain State.

---

## Заключение

Цифровой мир имеет смысл только тогда, когда изменения проходят через единый механизм исполнения.
