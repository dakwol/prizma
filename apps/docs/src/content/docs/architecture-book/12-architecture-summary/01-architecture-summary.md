# Архитектура «Призмы»

## Статус

Accepted

---

## Введение

Предыдущие разделы рассматривали архитектуру по частям.

Отдельно были определены:

- цифровой мир;
- объекты и их состояние;
- события и отношения;
- исполнение изменений;
- транзакции;
- проекции;
- синхронизация;
- наблюдаемость;
- надёжность;
- производительность;
- жизненный цикл данных;
- эксплуатация;
- верификация;
- эволюция архитектуры.

Но в работающей системе эти механизмы не существуют независимо.

Они образуют один непрерывный процесс существования цифрового мира.

---

## Архитектура как цепочка

В упрощённом виде:

```text
Reality
  │
  ▼
Observation / Intent
  │
  ▼

  │
  ▼

  │
  ▼
Domain Model
  │
  ▼

  │
  ▼

  │
  ├── History
  ├── Events
  └── Projections
          │

      Consumers
```

Вокруг этой цепочки постоянно работают:

```text
Security
Observability
Reliability
Performance
Data Lifecycle
Operations
Verification
Governance
```

## Не набор сервисов

Архитектура «Призмы» определяется не количеством backend-сервисов.

Не базой данных.

Не брокером.

Не MapLibre.

Не конкретным cloud provider.

Все эти вещи являются реализацией.

Архитектурой является модель того:

- что существует;
- кто чем владеет;
- как изменяется состояние;
- где проходят границы согласованности;
- как распространяются изменения;
- как система сохраняет свои свойства при отказах и развитии.

---

## Пример

Автомобиль передал новую координату.

Для пользователя это может выглядеть как простое движение значка на карте.

Внутри системы происходит цепочка:

```text
GPS observation
      │
      ▼
Integration Adapter
      │
      ▼
Normalized input
      │
      ▼
Execution
      │
      ▼
Domain rules
      │
      ▼
Transaction
      │
      ▼
State / telemetry persisted
      │
      ▼
Projection updated
      │
      ▼
Realtime delivery
      │
      ▼
Map displays new position
```

При этом параллельно:

- проверяется identity источника;
- сохраняется trace;
- измеряется latency;
- применяются retry policies;
- обновляется история;
- lifecycle policy определяет срок хранения;
- verification доказывает корректность реализации.

---

## Архитектурное значение

Архитектура «Призмы» является архитектурой непрерывно изменяющейся модели мира.

Её центральная задача — не просто хранить данные.

Она должна сохранять смысл цифрового мира при постоянном потоке изменений.

Чтобы увидеть эту модель целиком, необходимо ещё раз определить её центр — цифровой мир.
