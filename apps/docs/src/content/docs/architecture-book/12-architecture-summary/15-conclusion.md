# Заключение

## Статус

Accepted

---

## Что определяет эта книга

Эта книга не является инструкцией по написанию конкретного сервиса.

Она определяет фундаментальные правила, по которым существует цифровой мир «Призмы».

```text
Objects exist
States change
Relations connect
Events describe
History accumulates
Projections represent
Systems synchronize
```

---

## Главная идея

«Призма» рассматривает реальность не как набор строк в таблицах и не как набор маркеров на карте.

Она строит связанную цифровую модель мира.

```text
Real World
    │
    ▼
Digital Model
    │
    ▼
Understanding
    │
    ▼
Action
```

---

## Изменение как центральный процесс

Мир не статичен.

Поэтому архитектура строится вокруг контролируемого изменения.

```text
Observe
  │
Interpret
  │
Execute
  │
Commit
  │
Propagate
  │
Observe again
```

Этот цикл продолжается всё время существования платформы.

---

## История имеет значение

Текущее состояние показывает только один кадр.

История позволяет понимать:

- как объект изменялся;
- почему возникло состояние;
- какие события ему предшествовали;
- какие отношения существовали раньше.

Поэтому время является частью модели мира.

---

## Архитектура должна переживать реализацию

Первый production deployment «Призмы» не будет последним.

Через годы изменятся технологии и масштабы.

Архитектурная книга нужна именно для того, чтобы эти изменения происходили внутри понятной системы координат.

---

## Практический переход

После завершения этой книги следующий вопрос уже не:

> какой должна быть архитектура вообще?

Он становится конкретным:

> как построить первую production-реализацию этой архитектуры?

И здесь начинается следующий документ — **Technical Architecture**.

В нём можно перейти от принципов к конкретике:

```text
C#
PostgreSQL / PostGIS
Realtime
React
MapLibre
Three.js
Object Storage
Edge
Deployment
Repository
```

Каждый выбор будет оцениваться не изолированно, а относительно уже определённых архитектурных требований.

---

## Финальная мысль

Хорошая архитектура не пытается предсказать каждую будущую функцию.

Она создаёт систему правил, внутри которой новые функции можно добавлять без потери целостности.

Для «Призмы» такой системой является цифровой мир и контролируемый процесс его изменения.

```text
Reality changes
      │
      ▼
Prizma understands
      │
      ▼
Digital World changes
      │
      ▼
History remains
```

На этом фундаментальная архитектурная модель платформы завершена.
