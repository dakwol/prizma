# Призма

«Призма» — фундаментальный репозиторий платформы компании «СБОРКА».

Платформа предназначена для построения единой цифровой модели предприятия, территории
или другого физического мира. Она должна объединять пространство, объекты, людей,
транспорт, оборудование, медиа, телеметрию, события, историю, процессы и автоматические
сценарии.

## Текущий статус

Проект находится на стадии архитектурного проектирования. В репозитории создана
структура monorepo, сайт архитектурной документации, место для будущих частей платформы
и базовые инженерные настройки.

Backend пока не реализован. Для него оставлен каталог `backend/` с описанием будущих
границ, без генерации solution, проектов и бизнес-логики.

## Структура репозитория

```text
.
├── apps/docs/        # сайт архитектурной документации Astro + Starlight
├── backend/          # место для будущего backend
├── frontend/         # место для будущего продуктового frontend
├── packages/         # место для будущих общих пакетов workspace
├── infrastructure/   # место для будущей инфраструктуры
├── tools/            # место для будущих инженерных инструментов
└── docs/             # место для будущей внутренней инженерной документации
```

Основной источник архитектурной книги находится в
`apps/docs/src/content/docs/architecture-book`.

## Требования

- Node.js 22 LTS или новее в рамках актуальной LTS-линейки.
- pnpm 11 или новее.
- Corepack включён локально или pnpm установлен отдельно.

## Установка и разработка

```bash
pnpm install
pnpm dev
```

Сайт документации запускается из workspace-пакета `@sborka/prizma-docs`.

## Проверки и сборка

```bash
pnpm lint
pnpm format:check
pnpm check
pnpm build
pnpm quality
```

`pnpm quality` выполняет lint, проверку форматирования, Astro check и сборку
документации.

## ADR и RFC

ADR фиксируют принятые архитектурные решения. Новые ADR создаются из шаблона:
`apps/docs/src/content/docs/adr/template.md`.

RFC используются для предложений, которые требуют обсуждения. Новые RFC создаются из
шаблона: `apps/docs/src/content/docs/rfc/template.md`.

Не создавайте ADR о backend-технологиях до совместного решения команды и будущего
backend-разработчика.

## GitHub Pages

Документация публикуется из `apps/docs/dist` workflow `deploy-docs.yml`. После создания
GitHub-репозитория нужно заменить или подтвердить placeholder
`REPLACE_WITH_GITHUB_REPOSITORY_URL` в конфигурации документации и проверить base path
GitHub Pages.

Mermaid-диаграммы пока не подключены: проверенная стабильная интеграция должна быть
выбрана отдельным изменением, чтобы не ломать сборку документации.

## Лицензия

Проект пока не является open source. Лицензия будет определена отдельным архитектурным и
юридическим решением. До этого момента использование, копирование, модификация и
распространение исходного кода без письменного разрешения правообладателя не допускаются.
